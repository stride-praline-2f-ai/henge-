## Evidence and action

- Duo process CPU averaged3.27 core equivalents across254 comparable seconds. Generated JIT work dominated busy profiler samples; three software-TLB loads accounted for24.77% of sampled JIT instructions. Kernel-cache99.5% hits are conditional on ordinary TLB misses, not all guest accesses. Action: reduce redundant generated lookups through existing checked grouping, including stack writeback spans, instead of deleting permission/PAN/ASID checks or enabling a second MMU cache.
- Duo Metal4 compilation total9.743s/max781.84ms; iPad prior tail12.838s/max638.24ms. These are host compiler times, not exclusive frame stalls. Action: bounded optional compilation at utility QoS, correct existing classic pipelines while warming, pressure admission without a render-thread lock wait, immutable bundled display archive lookup independent of that lock. Required classic first-use compiles still exist. [Apple scheduling guidance](https://developer.apple.com/documentation/metal/using-the-metal-4-compilation-api), [keep the generic pipeline while specializing](https://developer.apple.com/videos/play/wwdc2023/10127/).
- GPU replay was already active: Duo43615 Metal4 submissions and0 reported guest GPU errors. Classic fallback also runs on the GPU; it does not mean CPU rendering. Exact compute219/4-byte no-op parity avoids an unnecessary fallback. The last rejected command did not identify every rejection, so bounded per-command hotspots now supplement reason totals. MetalFX encoded1647 frames with0 fallbacks, proving use but not a speed benefit.
- Duo8GiB guest RAM was successfully mapped in full. App footprint peaked4.61GiB and headroom stayed above1.89GiB, while system compression grew to2.63GiB and free pages were low. App headroom is not physically free RAM. No active balloon was found. Action: retain the existing event-driven pressure owner and bounded caches; avoid blindly inflating RAM/JIT/GPU residency. [Apple process allowance](https://developer.apple.com/documentation/os/os_proc_available_memory), [warnings may arrive too late](https://developer.apple.com/documentation/xcode/responding-to-low-memory-warnings). Full previous-run and OS termination data remain needed to classify the iPad crash.
- Network DNS completed134 requests without timeout/fallback. Storage was not continuously saturated in the measured final windows. That does not prove all app/asset loading is CPU-only. Action: adapt bounded receive batching fromPR176, validate real queue semantics and preserve DNS/lifecycle ownership; do not invent network throughput gains.

## Upstream and rejected shortcuts

Main remains e98920ce3b108d17f98acaff87f74e5a477ec4b2. PR186 ring/sysreg work andPR188 task/cache work overlap existing integrated functionality and require attribution rather than duplicate implementations. PR157's direct EL0 mapping remains an opt-in prototype, with physical iOS performance untested; shared address-space remapping cannot safely replace the current permission/invalidation model without dedicated mapping and fault validation. Its existence is not evidence that forcing it on fixes browser latency. [QEMU software-MMU and chaining constraints](https://www.qemu.org/docs/master/devel/tcg.html), [cross-vCPU invalidation](https://www.qemu.org/docs/master/devel/multi-thread-tcg.html).

PR161 is specifically rejected as a macOS27 default: [the driver investigation](https://github.com/Leviidev/Henge/pull/161#issuecomment-6863868526) identifies+0x68 as protectionOptions and event8 as disconnect on macOS27; emitting the older macOS15 timing interpretation stalled Duo desktop startup. Current timestamp writes remain absent and the legacy vblank experiment remains disabled by default. Do not present that ABI-dependent change as a general interrupt-storm fix.

No supported QoS setting guarantees P/E-core placement. Increasing vCPUs can increase coherence and scheduling work; the logs do not establish6 or8 as faster. Low Power Mode is an OS policy, not a measured core-affinity mechanism or an app-overridable frequency limit. Guest ARM64 privileged execution remains on the CPU; using Metal4 does not turn it into a GPU CPU emulator. No Retina, output resolution or refresh reduction is used for these improvements. Physical equivalent-work startup/FPS/latency/energy comparisons remain outstanding.

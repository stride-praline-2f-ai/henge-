# Upstream selection: 12 November 2026

Reviewed main `1812892e129c149cf68cfa0f5e26de7f92e94fba` against the
integrated VM base `8048e4a91450e1aa40bf8e6972b76c73921e038b`.
The intervening changes leave core/, devices/ and host/ unchanged. They add
Mac-app loader/AppKit/Chromium reservations, window presentation and input.
The shared iOS JIT edits reserve high virtual-address blocks for Chromium,
release them before VM allocation and reposition the writable alias when needed.
They do not reduce VM instruction count, software MMU lookups or guest shader
compilation. Do not reserve those blocks for a VM-only speed claim or replace
our validated VM renderer with the AppKit image presentation path.

PR #51 (`2ad95c2365f3358c28c8fc5087ed955ed5f2afcf`) contains an applicable
chunk-capacity fix. Ported it into our existing tail-recovery allocator, with
8-byte alignment for odd limits. The regression reproduces rejection of usable
space before the fix, passes after it, and retains concurrent allocation,
overflow, generation and tail tests under ASan/UBSan. This fixes HV_JIT_CAP
comparisons; it is not a measured desktop throughput improvement.

Do not import the complete experimental Rosetta engine for native ARM speed.
Its parity/adjust flags and software TSO implement Intel compatibility, with
additional barriers; the 4 KB software cache quarters coverage at equal entry
count and increases per-physical-page metadata. It is a separate compatibility
project, not a supported improvement for this native 16 KB desktop workload.

PR #112 (`8dff7fd8cf2bced01b98a58a6e738e0d5ec51156`) still updates a shared
non-atomic gpu_last_end from completion handlers and assumes arrival order.
Retain our optional synchronized timing counters; durations are not utilization.
PR #117 (`bc51b56e9e91e27d13ff4f1f48deb9a81360dd6f`) selected store-action
correction remains integrated and regression tested. Do not import its alternate
shader toolchain into the iOS 27 native replay path.
PR #32 (`385a4f6e4c60916ccff70ef736eda9d6cabe2932`) remains guest native-touch
compatibility rather than CPU translation optimisation; our sharing isolation
and optional, entitlement-gated touch path remain intact.
PR #80 aggressive QoS, #81 default superblocks, #78 larger fallback cache and
#92 full-surface hashing do not establish a win for the already cooled desktop.
Retain user choices, conservative defaults, zero-copy/damage-driven presentation
and bounded caches. No default CPU/RAM/refresh/Retina reduction or boost added.

Review is pinned and selective, not a claim of merging all upstream main/PRs.
Physical Duo/M4 desktop warmup and game performance still require comparison.
